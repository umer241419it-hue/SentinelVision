# SentinelVision — Known Issues & Test Artifacts

## Stage 5 Chaincode Schema & Hardening Test Artifacts

During the Stage 5 hardening passes and deployments of chaincode definition `basic` (v1.2 Sequence 2, v1.3 Sequence 3, and v1.4 Sequence 4) on `mychannel`, test invocations were executed to validate 9-field schema acceptance, endorsement policy enforcement, duplicate evidenceHash replay prevention, and assetID existence guards. The following artifacts relate to these verification passes:

### 1. `finding-stage5-test9` (Schema Validation Artifact in World State)
- **Asset ID**: `finding-stage5-test9`
- **Module Name**: `InferenceProvenance-Ed25519Seal`
- **Stored Signature**: `"TEST_SIGNATURE_PLACEHOLDER"`
- **Read-Time Status**: `signatureStatus: "TAMPERED"`
- **Explanation**: This record was submitted via CLI during Step 6 of Part B to prove that the newly deployed chaincode accepts 9 parameters and stores the `signature` attribute in world state. Because the signature provided was an explicit placeholder string (`"TEST_SIGNATURE_PLACEHOLDER"`) rather than a genuine 64-byte Ed25519 signature generated by `InferenceProvenance`'s private key, the read-time verification logic in `bridge/src/index.js` correctly flags this finding as `TAMPERED`.
- **Operational Impact**: This is an expected schema-validation test artifact, **not** a production finding or an authentic security compromise. It should be disregarded during demo queries.

### 2. `finding-stage5-endorse-test` (Multi-Org Endorsement Hardening Artifact)
- **Asset ID**: `finding-stage5-endorse-test`
- **Module Name**: `ModelIntegrity-NeuralCleanse-MAD-STRIP`
- **Stored Signature**: Genuine 64-byte Ed25519 signature (`ModelIntegrity` private key)
- **Read-Time Status**: `signatureStatus: "VALID"`
- **Explanation**: This finding was committed during Stage 5 Part C hardening to empirically verify that Fabric's multi-organization endorsement policy (`AND('Org1MSP.peer', 'Org2MSP.peer')`) is enforced at write time under the 9-field chaincode schema. The test verified that write transactions are rejected when Org2's peer is stopped, and succeed when both Org1 and Org2 endorse.
- **Operational Impact**: This is a Stage 5 hardening-pass artifact, permanently committed to the ledger world state. It is validly signed and endorsement-verified, but represents a test verification run rather than a production model inspection finding. Excluded from operational dashboards and demo views.
